# Prism 资源格式 v1

`.prism` 是 Prism Motion 唯一对外资源格式。裸 MP4/VAP、KTX/KTX2 不再作为资源入口接受；它们仅是容器内的完整原生载荷。格式版本、元数据 schema 与软件版本彼此独立。

## 布局

所有外层整数采用小端；原生载荷字节和内部字节序保持原样。偏移相对于 `.prism` 文件起点，不是 APK 起点。v1 只允许一份载荷，不压缩、不做 Base64、不包含路径。

| 区间 | 内容 |
| --- | --- |
| 0–63 | 固定文件头 |
| 64–127 | 统一元数据 |
| 128–191 | 单条载荷索引 |
| 192–4095 | 全零对齐填充 |
| 4096–EOF | 完整 VAP MP4 或 KTX2 载荷 |

### 文件头

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | 8 bytes | `50 52 49 53 4d 00 00 00` |
| 8 / 10 | u16 / u16 | 主/次版本：1 / 0 |
| 12 | u32 | 文件头长度：64 |
| 16 | u64 | 整个文件长度 |
| 24 / 32 | u64 / u64 | 元数据位置/长度：64 / 64 |
| 40 | u64 | 索引位置：128 |
| 48 | u32 | 载荷数量：1 |
| 52 | u32 | flags：0 |
| 56 | u32 | 前缀 CRC32 |
| 60 | u32 | 保留：0 |

CRC32 使用 IEEE 多项式 `0xedb88320`、初值/最终异或 `0xffffffff`；覆盖前 192 字节，计算时把 56–59 四字节视为零。

### 统一元数据

下表偏移相对于文件起点；字段都是 u32。

| 偏移 | 含义 |
| --- | --- |
| 64 | schema：1 |
| 68 / 72 | 逻辑宽 / 高 |
| 76 | 帧数 |
| 80 / 84 | 恒定帧率分子 / 分母 |
| 88 | 透明语义：0 不透明、1 straight、2 premultiplied |
| 92 | 色彩空间：1 sRGB |
| 96–127 | 保留，全零 |

尺寸、帧数和帧率项必须为正且不超过有符号 Int 范围。时长由 `frameCount × fpsDenominator × 1000 / fpsNumerator` 推导并向下取整；溢出拒绝。容器能表达有理帧率；当前播放后端仅支持整数 CFR，对其它帧率明确失败，不静默取整。

逻辑尺寸不同于 VAP 编码视频尺寸。原生载荷仍保留播放器所需的派生配置；打包工具从同一次输入生成外层与内层配置，探测器和播放器校验一致性。自动播放、循环次数、缩放方式属于播放请求，不是资源协议。

### 载荷索引

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 128 | u32 | 类型：1 VAP MP4、2 KTX2 |
| 132 | u32 | 保留：0 |
| 136 | u64 | 载荷起点：4096 |
| 144 | u64 | 非零载荷长度 |
| 152–183 | 32 bytes | 载荷原始字节的 SHA-256 |
| 184–191 | u64 | 保留：0 |

v1 要求 `payloadOffset + payloadLength == fileSize`，不允许重叠、尾随内容、未知 flags/枚举或非零保留字节。当前跨平台 API 的 u64 可用范围受有符号 Long 限制，超过范围直接拒绝。字节数组写入/软件解码另受 Int 大小限制，不能据此宣称支持任意大小文件。

## 当前载荷范围

v1 打包器生成单 level、多层（帧）的 RGBA8 或 ASTC 4×4 / 6×6 / 8×8 KTX2，或含 `vapc` 的 H.264 VAP MP4。不是对任意 KTX2 扩展、任意 MP4 视频编码的支持承诺；不支持的原生结构须明确失败。当前 OpenH264 路径不宣称支持 B-frame 延迟帧 flush。

## 加载与校验

- 按载荷类型选择引擎，不能从共享后缀推断引擎；显式选错引擎不降级。
- 文件/资产播放只读取前缀，再以原文件的 `offset/length` 区域交给底层播放器，不提取临时 MP4/KTX。
- Android APK 必须设置 `noCompress += "prism"`；实际资产区域为 `AssetFileDescriptor.startOffset + payloadOffset`，长度为 `payloadLength`。描述符由每个读/播放会话独立持有，不能提前关闭或共用可变 seek 指针。
- JVM 当前软件解码会物化限定载荷到内存，并验证摘要；这不是整个播放链路的零拷贝承诺。Android KAP 不支持内存来源，明确拒绝；Android VAP 内存来源会复制指定载荷，不落临时文件。
- `probe/check` 执行完整 CRC32、填充、SHA-256 与原生结构/元数据校验。默认 Android 播放只做前缀和原生字段检查，避免每个实例启动时通读整个载荷；下载/导入方应先执行完整校验。CRC/SHA 用于完整性，不提供来源认证。
- 原播放器已有的 Zstd 解压缓存不属于容器提取；新打包器当前生成未启用超压缩的纹理载荷。不能把底层已有缓存行为描述成整个链路绝无缓存文件。

协议实现见 [PrismContainer](<../prism-motion-format/src/commonMain/kotlin/com/zxhhyj/prism/motion/format/PrismContainer.kt>)；统一模型见 [PrismMetadata](<../prism-motion-format/src/commonMain/kotlin/com/zxhhyj/prism/motion/format/PrismMetadata.kt>)。
